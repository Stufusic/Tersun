# G6R.1 Workload Forensic Dossier: W1 (Fibonacci)

## 1. Workload Definition
- **Name**: Recursive Fibonacci ($N=30$)
- **Algorithm**: Đệ quy nhị phân $F(n) = F(n-1) + F(n-2)$ với $F(0)=0, F(1)=1$.
- **Source**: `benchmarks/forensics/inputs/w1_fibonacci.stn`
- **Tập trung điều tra**: Call/Return dispatch overhead, chi phí tạo/hủy function frame, đệ quy sâu, JIT compilation economics ROI.

## 2. Expected Behavior
- Số lượng lời gọi hàm: $2,692,538$ calls.
- Số lượng return: $2,692,538$ returns.
- Không có cấp phát động trên heap (0 allocations), 0 GC pressure.
- Cực kỳ nhạy cảm với chi phí tạo và giải phóng activation frame trên mỗi call.

## 3. Benchmark Baseline
- Input Checksum: `832040` (xác thực bit-exact 100%).
- Môi trường: Windows 11 x64, Intel Core i5-1245U, GCC 15.2.0 C++20.

## 4. Cold Results
- Cold Process Wall-Clock: **416.75 ms**
- Internal Cold Execution Time: **401.76 ms**
- Startup/Teardown Delta: **14.99 ms**

## 6. Opcode Profile

## 7. Tier Profile
- Baseline JIT ($M2$) đạt tốc độ 14.07 ms, nhanh hơn 28 lần so với Interpreter thuần.
- Auto-Tier ($M3$) đạt 14.90 ms do có thêm chi phí profiling feedback trước khi thăng hạng.
- JIT ROI: $\frac{398.70 - 14.07}{0.5} \approx 769\times$, chứng minh JIT compilation tax hoàn toàn được bù đắp trong đệ quy sâu.

## 8. Memory / GC Profile
- Objects allocated: 0
- GC Pause Total: 0 ns (GC hoàn toàn không tham gia vào hot path).

## 9. Specialization Profile
- Mảng: Không sử dụng.
- Đối tượng: Không sử dụng.

## 10. A/B Experiments
- **$E6$ (JIT Economics)**: Interpreter ($251.77$ ms) vs JIT ($14.07$ ms) $\rightarrow$ Tăng tốc $17.9\times$ khi loại bỏ hoàn toàn call frame interpretation.

## 11. Suspects
- Suspect 1 (R3): Overhead tạo và hủy call frame ngăn xếp.
- Suspect 2 (R8): JIT compilation tax vs runtime speedup.
- Suspect 3 (R7): GC overhead.

## 12. Confirmed Root Cause
- **PRIMARY ROOT CAUSE**: Call/frame allocation and dispatch overhead trong Interpreter mode. Mỗi lời gọi hàm tốn chi phí kiểm tra boundary và cập nhật con trỏ `call_stack_`.
- **SECONDARY CAUSE**: Thiếu Tail-Call Optimization và Self-Recursion Inlining trong Baseline JIT so với LLVM Native AOT.

## 13. Rejected Hypotheses
- **REJECTED**: GC pressure (hoàn toàn 0% đóng góp vào runtime).
- **REJECTED**: Array representation (không sử dụng mảng).
- **REJECTED**: Field IC (không sử dụng struct/object).

## 14. Recommended Fix for G6R.2
1. Triển khai **Fixed-Size Frame Recycling Pool** trong Interpreter: tái sử dụng frame đã cấp phát cho cùng mức đệ quy thay vì cấp phát lại.
2. Bổ sung **Recursive Call Unrolling** và **Register Calling Convention** trong Tier-1/Tier-2 JIT để thu hẹp khoảng cách 14.07 ms ↔ 2.54 ms.

## 15. Expected Metric Movement
- `function_frame_create` overhead $\downarrow$ 60%.
- JIT Execution time $\downarrow$ từ 14.07 ms xuống $< 5.0$ ms.
