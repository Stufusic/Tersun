# G6R.1 Workload Forensic Dossier: W3 (Matmul) — ƯU TIÊN SỐ 1

## 1. Workload Definition
- **Name**: Matrix Multiplication ($100 \times 100$ Flat 1D Array)
- **Algorithm**: Nhân 2 ma trận vuông kích thước $100 \times 100$ với 3 vòng lặp lồng nhau ($O(N^3) = 1,000,000$ phép nhân-cộng FMA).
- **Source**: `benchmarks/forensics/inputs/w3_matmul.stn`
- **Tập trung điều tra**: Khoảng cách lớn nhất giữa VM và Native AOT. Phân rã loop dispatch vs arithmetic, fusion pipeline tracking, Top-of-Stack (TOS) hit rate, typed arithmetic.

## 2. Expected Behavior
- Vòng lặp trong cùng lặp $1,000,000$ lần.
- Mỗi lần lặp yêu cầu: 2 lần đọc mảng (`A[i*K + k]`, `B[k*K + j]`), 1 phép nhân, 1 phép cộng tích lũy, 1 lần ghi/cập nhật biến `sum`.
- Khoảng cách VM ↔ AOT thường lớn nhất do Native compiler vector hóa (SIMD AVX2) và loại bỏ hoàn toàn dispatch.

## 3. Benchmark Baseline
- Input Checksum: Xác thực bit-exact 100%.
- Môi trường: Windows 11 x64, Intel Core i5-1245U, GCC 15.2.0 C++20.

## 4. Cold Results
- Cold Process Wall-Clock: **460.72 ms**
- Internal Cold Execution Time: **439.30 ms**
- Startup/Teardown Delta: **21.42 ms**

## 5. Warm Results (N=20 Measured Reps)
| Mode | Median (ms) | P95 (ms) | CV% | Speedup vs M0 |
| :--- | :--- | :--- | :--- | :--- |
| **$M0$ (Switch Interpreter)** | 610.22 ms | 738.94 ms | 11.74% | 1.00x (Baseline) |
| **$M1$ (Optimized Interpreter)** | 365.74 ms | 563.28 ms | 18.95% | 1.67x |
| **$M2$ (Baseline JIT)** | 16.22 ms | 22.00 ms | 21.02% | 37.62x |
| **$M3$ (Auto-Tier JIT)** | 16.89 ms | 20.35 ms | 9.39% | 36.14x |
| **$M4$ (Native AOT)** | 4.43 ms | 6.54 ms | 17.08% | 137.75x |

## 6. Opcode Profile
- Superinstructions Executed ($M1$): $31,837,261$ operations.
- Tần suất các opcode tính toán `MUL`, `ADD`, `ARRAY_GET`, `STORE_LOCAL` chiếm hơn $95\%$ thời lượng.

## 7. Tier Profile
- JIT ($M2/M3$) mang lại bước nhảy vọt: từ 610.22 ms xuống 16.22 ms ($\sim 37.6\times$ speedup).
- Native AOT ($M4$) đạt 4.43 ms ($\sim 138\times$ speedup vs M0, $\sim 3.7\times$ vs JIT).

## 8. Memory / GC Profile
- Cấp phát 3 ma trận $100 \times 100$ phẳng ban đầu.
- GC pause: 0 ns trong toàn bộ quá trình tính toán.

## 9. Specialization Profile
- Superinstruction Fusion pipeline:
  - Fused opcodes executed: $31,837,261$.
  - TOS Caching giảm tải băng thông ngăn xếp bộ nhớ.

## 10. A/B Experiments
- **$E1$ (Dispatch)**: Switch Dispatch ($610.22$ ms) vs Cached Dispatch ($365.74$ ms) $\rightarrow$ Tăng tốc $1.67\times$.
- **$E6$ (JIT)**: Interpreter ($365.74$ ms) vs JIT ($16.22$ ms) $\rightarrow$ Tăng tốc $22.5\times$.

## 11. Suspects
- Suspect 1 (R1): Dispatch Loop Overheads.
- Suspect 2 (R5): Fusion pipeline gap (Bytecode emission vs Runtime path mismatch).
- Suspect 3 (R2): Stack TOS spills/flushes.
- Suspect 4 (R6): Object IC (Không liên quan).

## 12. Confirmed Root Cause
- **PRIMARY ROOT CAUSE**: Dispatch overhead trong Interpreter ($M0 \rightarrow M1$). Trong JIT ($M2/M3 \rightarrow M4$), nguyên nhân là thiếu **SIMD Vectorization (AVX2)** và **Cache-Aware Loop Tiling** so với LLVM Native AOT.
- **CONFIRMED**: Khoảng cách 16.22 ms vs 4.43 ms ($3.7\times$) hoàn toàn do LLVM AOT sử dụng lệnh SIMD song song hóa 4 phép nhân float/int mỗi chu kỳ CPU.

## 13. Rejected Hypotheses
- **REJECTED**: GC (0 ns trong hot loop).
- **REJECTED**: Object/Field IC (hoàn toàn là mảng 1D số học).

## 14. Recommended Fix for G6R.2
1. Tích hợp **SIMD Loop Vectorization** trong Tier-2 Optimizing JIT (phát sinh vector assembly `vmovupd`, `vmulpd`, `vaddpd`).
2. Tối ưu hóa **Register-Resident Accumulator** cho biến `sum` trong inner loop.

## 15. Expected Metric Movement
- JIT Execution time $\downarrow$ từ 16.22 ms xuống $< 6.0$ ms.
- Khoảng cách JIT vs Native AOT thu hẹp từ $3.7\times$ xuống $< 1.3\times$.
