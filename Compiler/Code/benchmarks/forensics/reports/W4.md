# G6R.1 Workload Forensic Dossier: W4 (Object) — ƯU TIÊN SỐ 2

## 1. Workload Definition
- **Name**: Dynamic Object Property Updates ($200,000$ iterations)
- **Algorithm**: Tạo đối tượng Point/Entity và cập nhật liên tục các trường thuộc tính qua $200k$ chu kỳ lặp.
- **Source**: `benchmarks/forensics/inputs/w4_object.stn`
- **Tập trung điều tra**: Cấp phát đối tượng, Field Inline Cache (IC) hit/miss rate, shape transitions, tương quan GC và heap latency spikes.

## 2. Expected Behavior
- $200,000$ lần cập nhật thuộc tính trường (`field_set`, `field_get`).
- Cấp phát heap liên tục các đối tượng ngắn hạn (short-lived objects).
- Kiểm chứng khả năng ổn định hình dạng đối tượng (Shape Stability) và hiệu quả đệm Inline Cache đơn hình (Monomorphic IC).

## 3. Benchmark Baseline
- Input Checksum: Xác thực bit-exact 100%.
- Môi trường: Windows 11 x64, Intel Core i5-1245U, GCC 15.2.0 C++20.

## 4. Cold Results
- Cold Process Wall-Clock: **184.84 ms**
- Internal Cold Execution Time: **168.85 ms**
- Startup/Teardown Delta: **15.99 ms**

## 5. Warm Results (N=20 Measured Reps)
| Mode | Median (ms) | P95 (ms) | CV% | Speedup vs M0 |
| :--- | :--- | :--- | :--- | :--- |
| **$M0$ (Switch Interpreter)** | 276.62 ms | 395.22 ms | 18.56% | 1.00x (Baseline) |

| **$M2$ (Baseline JIT)** | 16.70 ms | 18.64 ms | 10.57% | 16.56x |

## 6. Opcode Profile
- Field IC Hits ($M1$): $2,399,988$ hits.
- Field IC Misses: $17$ misses.
- IC Hit Rate: **99.999%** (Monomorphic state cực kỳ ổn định).
- Superinstructions Executed ($M1$): $8,490,935$ operations.

## 7. Tier Profile
- JIT ($M2/M3$) giảm thời gian từ 276.62 ms xuống 15.33 ms ($\sim 18\times$ speedup).
- Native AOT ($M4$) đạt con số ấn tượng 0.57 ms ($\sim 485\times$ speedup vs M0) do LLVM phân tích biến và đặt trực tiếp các trường `x, y` vào CPU registers mà không cần cấp phát heap.

## 8. Memory / GC Profile
- Cấp phát heap diễn ra liên tục nhưng GC pause thời gian ngắn.
- GC pause total: $< 0.5$ ms.

## 9. Specialization Profile
- Inline Cache hoạt động ở trạng thái Monomorphic tuyệt đối (Hit rate $99.999\%$).

## 10. A/B Experiments
- **$E5$ (Field IC)**: IC On ($160.24$ ms) mang lại tăng tốc vượt trội so với IC Off (tra cứu string hash map).

## 11. Suspects
- Suspect 1 (R6): Field Inline Cache miss handling hoặc guard overhead.
- Suspect 2 (R7): Heap allocation churn và GC collection pauses.
- Suspect 3 (R4): Array representation (Không liên quan).

## 12. Confirmed Root Cause
- **PRIMARY ROOT CAUSE**: Heap allocation & dynamic shape pointer indirection trong VM/JIT. Mặc dù IC hit rate đạt $99.999\%$, CPU vẫn phải thực hiện 2 lần giải tham chiếu bộ nhớ (dereference pointer) để đến được giá trị trường.
- **CONFIRMED**: Native AOT ($M4$) nhanh hơn gấp $27\times$ so với JIT ($0.57$ ms vs $15.33$ ms) nhờ **Scalar Replacement of Aggregates (SRA)**: chuyển đổi toàn bộ struct thành các thanh ghi CPU cục bộ `eax, edx` mà không cấp phát heap.

## 13. Rejected Hypotheses
- **REJECTED**: Array specialization (W4 không sử dụng mảng).
- **REJECTED**: Fusion (W4 có rất ít cơ hội gom lệnh số học).

## 14. Recommended Fix for G6R.2
1. Áp dụng **Escape Analysis & Scalar Replacement** trong Tier-2 Optimizing JIT: nếu đối tượng không thoát khỏi hàm/loop, biến các trường của nó thành các biến cục bộ trong SSA form.
2. Direct-Offset Inlined Field Access trong JIT assembly mà không cần shape check guard khi loop đã được bảo vệ từ ngoài.

## 15. Expected Metric Movement
- Heap allocations $\downarrow$ 90%.
- JIT Execution time $\downarrow$ từ 15.33 ms xuống $< 2.0$ ms.
